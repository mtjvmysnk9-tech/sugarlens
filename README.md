# 隐糖 SugarLens

评估每日「隐形糖」摄入量的移动端 H5 原型：把常见食品换算成方糖数，用红绿灯提示超标风险，并给出低糖替代建议。

线上地址（本仓库经 GitHub Pages 部署）：<https://mtjvmysnk9-tech.github.io/sugarlens/>
正式站点（含真实上报）：<https://sugarlens-t3tamdheczu.qoder.zone/>

## 我做的部分

- 产品定义：目标用户（控糖但不会读配料表的人）、核心任务（30 秒内记完一笔）、四个页面（今日 / 记录 / 报告 / 我的）的信息架构与跳转逻辑。
- 数据口径设计：每日 25g 理想值、50g 上限（WHO 与中国居民膳食指南）；统计以「人·日」为单位而不是以记录条数为单位，避免记得多的人被放大。
- 食物糖量清单：22 项常见食品饮料的份量与含糖量估算，按红绿灯分级。
- 后台呈现范围决策：管理端只读聚合统计，不落单条明细，降低隐私面。
- 代码由 AI 辅助生成，我负责需求拆解、口径定义、逐条验收与线上验证。

## 结构

| 文件 | 作用 |
| --- | --- |
| `index.html` / `app.js` / `styles.css` | 访客端单页应用，记录保存在浏览器 `localStorage` |
| `admin.html` / `admin.js` / `admin.css` | 管理端仪表盘，读取服务端聚合接口 |

无构建步骤、无依赖包，纯静态。`img/` 下 22 张食物配图为 AI 生成的统一风格插画，压到 160px WebP（合计约 100KB），文件名与食物编号一一对应。

## 两处部署的差别

后端接口跑在另一台主机上，网关对写操作校验 `Origin`，只接受来自正式站点自身的请求。因此同一份代码在 GitHub Pages 上会自动降级：

| | 正式站点 | 本仓库（GitHub Pages） |
| --- | --- | --- |
| 记录与报告 | 本机保存 + 匿名上报 | 仅本机保存，「本地演示模式」 |
| 管理端聚合数据 | 可读 | 可读（读接口 CORS 开放） |

判定逻辑在 `app.js` 顶部（`ON_GH_PAGES` / `REPORTING`）和 `admin.js` 的 `API` 常量，改动后两处部署共用一套源码。

## 数据说明

- 食物含糖量为常见份量的估算值，参考包装营养标签与《中国食物成分表》的量级，仅用于原型演示，不构成营养建议。
- 正式站点上有用于演示的批量样例记录，与管理端看到的早期数字来自同一批数据。
